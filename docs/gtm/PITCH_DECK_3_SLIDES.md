# Ghost Fabric — Customer pitch deck (GF-30)

Three-slide narrative for energy and telecom discovery. Copy into PowerPoint/Keynote/Google Slides. Keep safety ribbon language on every leave-behind.

---

## Slide 1 — Problem

**Title:** Critical networks still fail slowly — and without proof of control

**Energy angle**

- Control and communications node loss stretches restoration while teams reconstruct topology and decisions by hand.  
- Industry downtime cost framing is often cited in the multi‑million‑dollar-per-hour range for severe grid events — treat as **market context**, not a Ghost Fabric measurement.

**Telecom angle**

- Regional handoffs are hard to see in one shared timeline.  
- Operators need failover path clarity without trusting opaque automation.

**Bottom line**

Resilience tools that cannot replay, attribute approval, and export evidence do not survive procurement or audit.

## Slide 2 — Solution

**Title:** Ghost Fabric — Resilience OS for mission-critical distributed networks

**Four pillars (one coherent loop)**

| Pillar | Operator moment |
|--------|-----------------|
| **CHAMELEON** | Node loss → coordinator handoff → route recomputation |
| **PROPHET** | Labeled synthetic evidence ramp with uncertainty / FP guardrails |
| **MIRROR** | Bounded fictional tabletop branches (review only) |
| **PHOENIX** | Human-approved, reversible workflow recovery |

**Platform foundations already running**

- Versioned REST `/api/v1` + OpenAPI contract  
- Viewer / operator bearer roles  
- PostgreSQL durable audit + idempotent commands  
- Console with session, health, and confirmation gates  

**Safety:** Synthetic or approved training data; human approval required; no operational targeting.
